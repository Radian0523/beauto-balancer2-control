# 処理の流れ (v5、2026-09-28 16:30 時点の標準)

v5 がどう制御しているかを、処理の順にまとめたもの。
それぞれの処理について、純正サンプルかどうか、制御の名前で言うと何か、なぜそうしたか、を書く。
コードは `firmware/main.c`、調整値は `docs/05_開発手順.md` を参照。

## 0. ひとことで言うと

**純正の「4 状態フィードバック」をそのまま土台にしている。そこに次の 2 つを足した。**

- **2 自由度制御**: 滑らかな目標軌道を作り、加速に合わせて前傾させる
- **推定**: 車輪速度、釣り合う角度、ジャイロの 0 点をそれぞれ推定する

構造は**カスケード制御 (二重ループ)**:

- 外側: 倒立の状態フィードバック。500 Hz で電流指令を出す
- 内側: 純正の電流 PI 制御。1 kHz で指令どおりの電流を流す

PID ではない。4 状態フィードバックは LQR や極配置で設計するのと同じ形。ゲインは純正の値を使っている。

```
 コントローラ              ① 目標軌道             ③ 状態フィードバック               電流制御 (純正)
 (スティック・R1/R2) ──→  + 前傾 FF      ──→   (純正 Control() の形)       ──→  PI, P×4        ──→ モータ
                          v_cmd, th_ref          + 積分 + ずれの上限              1 kHz
                                                  ↑        ↑       ↑
                  ジャイロ → [純正] 傾き推定 ─────┘        │       │
                           ↑ ジャイロ 0 点の補正            │       │
                           釣り合う角度 th0 ────────────────┘       │
                  エンコーダ → ② 車輪速度オブザーバ ─────────────────┘
```

## 1. 1 周期 (500 Hz = 2 ms) の処理

走行中は、`main()` のループで毎周期この順に呼ぶ。

| 順 | 関数 | 何をするか | 純正 / 自作 | 制御の名前 |
|---|---|---|---|---|
| 1 | `CycleProc()` | センサーを読む。傾きを推定する。周期を待つ | **純正ライブラリ** | ジャイロ積分 + ハイパスフィルタ (リーク積分) |
| 2 | `gyro_trim()` | ジャイロの 0 点を、走りながら少しずつ合わせ直す | 自作 | バイアス推定 (長時間平均、ローパスフィルタ) |
| 3 | `pad_to_speed()` | スティックとボタンから、滑らかな目標速度と目標前傾を作る | 自作 | 軌道生成 (S 字加減速) + フィードフォワード = **2 自由度制御** |
| 4 | `wheel_observer()` | 車輪角から、滑らかな車輪角速度を推定する | 自作 | **状態オブザーバ** (2 次の追従オブザーバ) |
| 5 | `balance_zero()` | 釣り合う角度を覚え直す | 自作 | 平衡点の推定 (適応的なオフセット推定) |
| 6 | `control()` | 状態のずれにゲインを掛けて、電流指令を出す | **純正 `Control()` の形** + 自作の追加 | **状態フィードバック** + 積分 (サーボ系) + 飽和処理 |
| 7 | `log_sample()` | 走行ログを RAM に記録する | 自作 | (制御ではない) |
| 8 | 転倒の検出 | 45° 以上傾いた状態が 0.1 秒続いたら止める | 自作 (純正の判定も残している) | (安全処理) |
| — | 電流制御 (割り込み、1 kHz) | 電流指令どおりの電流をモータに流す | **純正ライブラリ** (P ゲインだけ 4 倍) | 電流 PI 制御 (カスケードの内側) |

## 2. 各処理の中身

### 1. 傾きの推定: 純正のまま

- ジャイロの角速度を積分して、本体の傾き `BODY_ANGLE` を出す。
- ずれが溜まらないように、ゆっくり 0 に戻す処理 (リーク、時定数 約 1.5 s) が入っている。
- 加速度センサーは使っていない。**スタートボタンを押したときの姿勢が 0°** になる。
- 弱点が 2 つある。
  - スタートのときの持ち方で、傾きがずれる。
  - ジャイロの 0 点が校正からずれると、そのぶん傾きがずれ続ける。
- この 2 つを、あとの `balance_zero()` と `gyro_trim()` で補っている。

### 2. ジャイロ 0 点の補正 (`gyro_trim`): 自作

- **考え方**: 立っている限り、傾く速さを長い時間で平均すると 0 になる。そこで、ジャイロの生の値を 5 秒 (`GTRIM`) で平均したものを 0 点として使い続ける。
- **制御の名前**: バイアス推定。1 次のローパスフィルタでジャイロのバイアスを追いかけている。カルマンフィルタでバイアスを状態に入れるのを、簡単にした形。
- **制限**
  - 1 回に効かせる値は ±1000 LSB まで。
  - 0 点は、校正の値から ±200 LSB より外には動かさない。
  - 倒れたときは、0.5〜1 秒前の値に戻す。
- **なぜ**: 校正の 0 点が回ごとに数〜数十 LSB ずれていた。そのせいで、止まっていても前に出ていった。

### 3. 目標軌道 + 前傾フィードフォワード (`pad_to_speed`): 自作

**入力**

| 入力 | 目標 |
|---|---|
| 左スティック上下 | 目標速度 (最大 `VMAX` 0.3 m/s、後退は `VBACK` 0.3 m/s まで) |
| 右スティック左右 | 旋回 |
| R1 (ゆっくりモード) | 押しているあいだ、スティックに触らなくても `VSLOW` 0.08 m/s で進む。旋回は半分の速さ |
| R2 (いそいそモード) | 押しているあいだ、`v_fast` で進む。◯/✖︎ で 0.05 m/s ずつ変えられる (0.1〜0.7 m/s) |

- スティックの中立は、スタートのときの値を基準にする。スティックは手を離しても、ぴったり 0 には戻らないため。

**軌道生成 (S 字加減速)**

- 目標速度に向かって、次の 3 つに上限をかけた滑らかな軌道 `v_cmd` を作る。
  - 速度: `VMAX`
  - 加速度: `ACC` 0.5 m/s²
  - 加速度の変化 (ジャーク): 3 m/s³

**前傾フィードフォワード**

- 加速度 a で進むとき、釣り合う前傾角は a/g になる。これを目標傾き `th_ref = -a/g` として ③ に渡す。
- **制御の名前**: **2 自由度制御**。
  - 目標への動きはフィードフォワードで作る。
  - 外乱やずれはフィードバックで直す。
  - この 2 つを分けて設計できる。

**なぜ**

- 純正は目標がいつも「直立」だった。そのため、加速しようと前傾すると、フィードバックが本体を起こそうとして逆らう。これが加速直後に倒れる原因になっていた。
- スティックの値をそのまま目標にすると、急な変化で機体が蹴られる。

### 4. 車輪速度オブザーバ (`wheel_observer`): 自作

- **考え方**: 車輪角 (エンコーダ) の測定値を、2 次のモデルで追いかける。推定した角速度を、車輪の速さとして使う。

  ```
  x̂' = v̂ + 2ω e,   v̂' = ω² e    (e = 測った車輪角 − 推定した車輪角、ω = 2π × 20 Hz、臨界減衰)
  ```

- **制御の名前**: **状態オブザーバ** (追従オブザーバ。PLL 型や α-β フィルタと同じ仲間)。
- **なぜ**
  - 純正は、エンコーダの差分をそのまま速度にしていた。1 カウントが 6.2 rad/s 刻みと粗い。
  - 速度のゲインがこのガタつきを増幅して、電流が ±2500 ほど揺れていた。

### 5. 釣り合う角度の推定 (`balance_zero`): 自作

- **考え方**: 立っていて加速していないあいだ、本当の傾きの平均は必ず「釣り合う角度」になる。これは物理で決まる。そこで、加速していないあいだの `(傾き推定 − 目標前傾)` の平均を `th0` として覚える。③ では、`th0` からのずれを使う。
- **制御の名前**: 平衡点の推定 (適応的なオフセット補正)。
- **覚える速さ**
  - スタート直後の 3 秒は、時定数 0.7 s で速く覚える。
  - そのあとは 2 s (`BZT`) でゆっくり覚え直す。
- **制限**
  - 1 回に効かせるずれは ±0.1 rad (約 6°) まで。
  - `th0` は ±25° まで。
  - 加速・減速中は覚えない。
- **なぜ**: スタートのときに機体をまっすぐ持つのは無理。持ち方によらず、同じように走れるようにするため (再現性)。

### 6. 状態フィードバック (`control`): 純正 `Control()` の形 + 自作の追加

**純正と同じ部分**

- 次の 4 つの状態に純正のゲインを掛けて、足し合わせる。

  | 状態 | 純正のゲイン |
  |---|---|
  | 本体の傾き | K1 = -36400 |
  | 傾く速さ | K2 = -5460 |
  | 車輪角のずれ | K3 = 1320 |
  | 車輪角速度のずれ | K4 = 396 |

  ```
  電流指令 = K1·(傾き) + K2·(傾く速さ) + K3·(車輪角 − 目標車輪角) + K4·(車輪角速度 − 目標角速度)
  ```

- 左右の車輪の差 (角度差、角速度差) のフィードバックも、純正のまま。まっすぐ走るため。
- 目標車輪角は、目標角速度の積分。これも純正と同じ。
- **制御の名前**: **状態フィードバック** (レギュレータ)。LQR や極配置で出てくるのと同じ形。PID ではない。

**純正から変えたところ**

| 変えたところ | 制御の名前 | なぜ |
|---|---|---|
| 傾きは「直立」ではなく、`th0 + th_ref` からのずれを使う | 2 自由度制御の目標値 | 前傾フィードフォワードと、持ち方のずれを反映するため |
| 傾く速さも、目標前傾の変化の速さ `dth_ref` からのずれを使う | 同上 | 同上 |
| 車輪角速度は、オブザーバの値を使う | オブザーバによるフィードバック | 速度が粗くて電流が揺れていたため |
| 純正の単位の間違い (`T_SPD / MAIN_CYCLE`) を直した | (バグ修正) | 走行中、速度の項がブレーキになっていた |
| 走行中は、車輪角のずれ (左右の平均) を **±1 rad (約 2 cm、`EMAX`)** までにする | 飽和処理 (目標の引き戻し) | 大きく飛び出したあと、溜まったずれを一気に取り戻そうとして「進みすぎてキュッと戻る」を繰り返し、坂やシーソーで倒れていた。4 (約 8 cm) → 1 で解消 |
| 車輪の速さのずれ (前後の平均) を **±0.4 m/s (`SMAX`)** までにする | 飽和処理 | シーソーが傾いた瞬間などに車輪が走り出したとき、速さの項が大きすぎる力を要求しないように |
| 車輪角のずれ (左右の平均) の**積分**を足す (時定数 2 s、加速中は止める) | **積分動作 (サーボ系、1 型)**。加速中に止めるのはアンチワインドアップ | 坂で押し戻され続けて、下がりっぱなしになるため。左右別々に積分すると左右が逆向きに張り付いたので、左右の平均だけにした |
| R1 のあいだだけ、ゲインの倍率を切り替えられる (0.3 秒かけて) | **ゲインスケジューリング** | 今の標準では普段と同じ値 (KBAS=KWRS=1) なので、実質は何もしていない |

- ゲインの倍率 `KBA`、`KWR` などは、今はすべて 1 (純正のまま)。
- 1.3 / 1.25 も試した。シーソーには効いたが、満充電の電池で坂を登ると 3 Hz で揺れた。

### 電流制御: 純正ライブラリ (P ゲインだけ 4 倍、`KCP=4`)

- ③ の電流指令どおりの電流を、PI 制御でモータに流す (1 kHz)。
- **制御の名前**: 電流 PI 制御。カスケード制御の内側のループ。
- 変えたのは、起動時に純正の P ゲインを 4 倍にしたところだけ ([main.c](../firmware/main.c) の `main()` の最初)。制御のしくみは純正のまま。ゲインは memmap にあるので、起動のたびに書き換える (フラッシュには保存しない)。

  ```c
  memmap.values.GAIN_CURRENT_P *= K_CP;   /* 4 倍 */
  memmap.values.GAIN_CURRENT_I *= K_CI;   /* 1 倍 (そのまま) */
  ```

**電流制御がやっていること**

- 電流は直接は決められない。決められるのは、モータにかける電圧 (PWM の強さ) だけ。電圧をかけると、電流があとからついてくる。
- そこで毎回、次の電圧をかける。

  ```
  かける電圧 = P × (電流指令 − 今の電流)  +  I × (ずれの積み重ね)
  ```

  - P の項: 今のずれに比例した電圧を、すぐにかける。
  - I の項: ずれが残っているあいだ、電圧を少しずつ上げていく。

**P を上げると、電流が指令に届くのが速くなる理由**

- 純正の値は P = 0.00023、I = 0.012。I の項が主役で、P の項はほとんど効いていなかった。
  - 指令が変わっても、P の項の電圧が小さいので、電流はほとんど増えない。
  - I の項が電圧をじわじわ積み上げるのを待つことになる。
  - これに約 93 ms かかっていた (実験 B: 指令 1500 の段で測定)。
- P を 4 倍にすると、同じずれに対して 4 倍の電圧を、その瞬間にかける。
  - 電流が一気に増える。
  - 指令に近づくと、ずれが小さくなって電圧も下がり、行きすぎずに止まる。
  - 約 5 ms で届く。
- P を 8 倍にすると、強すぎる電圧で電流が指令を行きすぎる。逆向きにも強すぎる電圧がかかって、電流が細かく行ったり来たりする。

**電流が速く流れると、倒立が安定する理由**

- 状態フィードバックは、毎周期「今の状態」を見て電流指令を出す。電流が流れるのが遅いと、力が出たときには状態が変わっている。つまり「少し前の状態」に向けて力を出すことになる。
  - 傾き始めても、力がなかなか出ない。そのあいだに傾きが大きくなる。
  - 力がやっと出たときには、指令が大きくなっていて押しすぎる。今度は逆に傾く。
  - これを繰り返して、「行きすぎて戻る」揺れになる。
- 比べる相手は、倒れる速さ (時定数 83 ms。手を離すと 83 ms ごとに傾きが約 2.7 倍になる)。
  - 純正 (93 ms): 力が出るまでに、傾きが 2〜3 倍に広がってしまう。
  - KCP=4 (5 ms): 力が出るまでに、傾きはほとんど変わらない。
- **制御の言葉でいうと**: 内側のループの遅れが**位相遅れ**になり、外側のループの**位相余裕**を減らしていた。カスケード制御では、内側のループを、外側で抑えたい動きより十分速くする (目安は 5〜10 倍) のが基本。純正はここが同じくらいだった。

**試した結果**

| KCP | 結果 |
|---|---|
| 1 (純正)、2 | 止まることもできなかった |
| **4** | **前に進むのがすごく安定した**。細かい振動 (キュッキュッ) もはっきり減った |
| 8 | 強すぎて不安定 |

**電流の限界**

- 速いとき (0.45 m/s 以上) は、モータの逆起電力で電圧が足りなくなる。指令の 35% ほどしか電流が出ない。これは制御では直せない。**速さの上限を 0.3 m/s にしている理由**。
- 電池が減ると、出せる電流の上限も下がる (`./bb2 stats` の「電池の目安」。満充電で 700 前後、650 未満で揺れが収まりにくくなる)。

### 8. 転倒の検出: 自作 (純正の判定も残している)

- 釣り合う角度から 45° 以上傾いた状態が、0.1 秒続いたら止める。
- 純正の判定 (`isWhleeOverSpeed()`、車輪が 62.8 rad/s を超えたら止める) は、この機体では一度も働かなかった。全力でも 44〜50 rad/s しか回らないため。倒れたあとも、全力で空回りし続けていた。

## 4. 純正サンプルをどこまで使っているか

| 部分 | 純正のまま | 自作 |
|---|---|---|
| センサーの読み取り、傾きの推定 | ✔ (ライブラリ) | 0 点の補正だけ足した |

| 左右差のフィードバック | ✔ | — |
| 校正、変数のクリア | ✔ (`calibrarion()`、`ClearVariables()`) | 校正中の揺れの確認 |
| 目標軌道、前傾フィードフォワード | — | ✔ |
| 車輪速度オブザーバ | — | ✔ |
| 釣り合う角度、ジャイロ 0 点の推定 | — | ✔ |
| R1 / R2 / ◯✖︎ の操作 | — | ✔ |
| 転倒の検出、走行ログ | — | ✔ |

## 5. 使っていない機能 (コードには残してある)

| 機能 | 調整値 | 使っていない理由 |
|---|---|---|

## 6. シーソーを渡れるようになるまで

今の標準で「滑らかに渡れて、傾いた瞬間も倒れない」ようになったのは、次の 2 つの組み合わせから。

- **R1 のゆっくりモード**
- **走行中のずれの上限 2 cm (`EMAX=1`)**

### 経緯 (9/28)

| 時刻 | 入れたもの | 結果 |
|---|---|---|
| 昼 | 速さの上限を下げる (`VMAX=0.3`)<br>速さのずれに上限 (`SMAX=0.4`) | 初めて完走。ただし 4 回中 1 回だけ |
| 昼 | **R1 のゆっくりモード** (押しているあいだ 0.08 m/s で進み続ける) | 傾きそうになってもスティックを戻さずに、一定の速さで渡れるようになった |
| 14:25〜14:30 | 傾きと車輪の速さの効きを強く (`KBA=1.3`、`KWR=1.25`) | 3 回連続で完走。ただ、渡る途中は揺れていた (揺れ 20〜25°/s) |

### 効いたものと、その理由

**1. R1 のゆっくりモード**

- シーソーは、止まった状態で傾くと揺れが育って倒れる。一定の速さで這うように進んでいると、滑らかに渡れる。
- 傾きそうになると、人は思わずスティックを戻してしまう (13:38 に失敗した回)。R1 を押し続けるだけで一定の速さで渡りきれるので、操作のぶれがなくなった。

**2. `EMAX=1` (走行中のずれの上限を 2 cm)**

- シーソーが傾いた瞬間は、坂を下るのと同じで、車輪が前に飛び出す (0.7〜0.95 m/s)。
- 以前 (`EMAX=4`) は、そのとき溜まった目標とのずれ (最大 8 cm) を一気に取り戻そうとして、後ろに強く戻っていた。戻りすぎて本体が後ろに 15° ほど傾き、そのまま倒れていた。これが「進みすぎてキュッと戻る」の正体。
- 上限を 2 cm にすると、取り戻そうとする力が 1/4 になり、傾いた瞬間を耐えられるようになった。ずれが小さいうちの動きは、今までと同じ。

**3. 効きを公式の強さに戻した (`KBA=KWR=1`)**

- 強い効き (1.3 / 1.25) は、`EMAX=4` で傾いた瞬間に耐えるために入れていた。`EMAX=1` があれば、要らなくなった。
- 強い効きは、満充電の電池では揺れやすかった (坂では 3 Hz で揺れて倒れ、R1 では 60°/s)。公式の強さに戻して、渡る途中の揺れが 60 → 5°/s になった。

### 走らせ方のコツ (実際に走らせてわかったこと)

- シーソーの手前から R1 を押し続ける。傾いても離さない。
- 傾く瞬間に、シーソーの支点の近くにいるほうがよい。
- 機体がシーソーに対してまっすぐ (左右に曲がらず、正面を向いている) ほうがよい。
