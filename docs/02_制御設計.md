# 制御設計：何をもって「PIDを超える」のか

## 0. 結論（先に）

勝ち筋は **制御則の派手さではなく「推定」**。具体的には次の 4 つ。効果が大きい順。

| # | やること | 効く場面 | 実測（シミュレーション, 16試行） |
|---|---|---|---|
| 1 | **拡張カルマンフィルタで「傾き角・ジャイロバイアス・外乱トルク」を同時推定** | 全ゾーン、特に坂/シーソー | 角度推定誤差 **10.2° → 0.18°**、完走率 **81% → 100%** |
| 2 | **推定した外乱トルク（＝坂）を前置補償**（平衡姿勢を坂の分だけ倒す） | D/E ゾーン | 坂に入った瞬間から姿勢を切替。積分待ちが要らない |
| 3 | **LQI（速度追従サーボ）＋制御配分**（倒立を最優先、旋回は余ったトルクだけ） | S字・加速時 | S字での飽和による転倒を除去 |
| 4 | **ペースノート＋デッドレコニングのパス追従** | B/C ゾーン | 横ずれ **22 cm → 2.7 cm** |

「PID をやめて LQR にする」だけでは**ほぼ何も変わらない**（純正が既に状態FBなので）。差は推定で付ける。

## 1. モデル

状態 `x = [φ, θ, φ̇, θ̇]`（φ: 車輪の絶対回転角、θ: 本体の鉛直からの傾き）、入力 `u` = 左右合計の車輪トルク [Nm]。
勾配 α の路面で（導出は `src/params.py` の docstring と `src/model.py`）：

```
(m r² + Jw_eq)   φ̈ + m_b r l cos(θ+α) θ̈ − m_b r l sin(θ+α) θ̇² + m g r sin α = u − c(φ̇−θ̇)
(m_b l² + J_b)   θ̈ + m_b r l cos(θ+α) φ̈ − m_b g l sin θ                     = −u + c(φ̇−θ̇)
```

**重要な性質**：勾配 α は φ 側の式にしか現れない。つまり

```
坂  ≡  車軸まわりの一定外乱トルク  τ_d = − m g r sin α
```

坂・段差・積載の偏り・転がり抵抗は**全部まとめて 1 個の状態 τ_d** として扱える。これが設計全体の背骨。

**数値（公称値）**：不安定極 12.1 rad/s（**倒れる時定数 83 ms**）。500 Hz 制御なら 1 時定数あたり 41 サンプルなので余裕。
車輪側の等価慣性 `Jw_eq = 9.1e-5` のうち **97% がモータロータの換算慣性 `2 J_rotor n²`**（減速比 21 の二乗で効く）。
ここを無視したモデルは合わない。

## 2. 推定器：ここが本丸

### なぜ純正の HPF ではダメか

純正: `angle(t) = 0.9995·angle(t−1) + ω(t)·Δt`。これは**時定数 2 秒のハイパスフィルタ**。

- 坂で「傾いたまま静止」は定常状態なので、**HPF は必ずその傾きを 0 に引き戻す**。
  15° の坂で必要な前傾は約 3.1° だが、HPF はそれを見失う（＝3.1° の系統誤差）。
- ENC-03 は温度ドリフトが大きい。オフセット校正しても走行中にずれ続ける。
- 分解能が 1.2 deg/s しかない（量子化）。生の積分は不利。

### 代わりにやること：モデルベースの 6 状態カルマンフィルタ

```
推定状態  x̂ = [φ, θ, φ̇, θ̇, b_gyro, τ_d]
観測      y = [ enc = φ − θ ,  gyro = θ̇ + b_gyro ]
入力      u = 実際に出したトルク（飽和後の値を入れること）
```

加速度センサが無くても **絶対角 θ は可観測**。理由：本体が傾けば車輪が加速するので、
「エンコーダの動き ＋ 既知の入力トルク ＋ 運動方程式」から傾きが逆算できる。
実際に 6 状態の可観測性ランク＝6 を数値で確認済み（`python3 src/design.py`）。

- ゲインは**定常カルマンゲイン**をオフレイン計算（`scipy.solve_discrete_are`）→ C には 6×2 の定数行列を焼くだけ。
  LPC1343（FPUなし）でも 500 Hz で余裕（1 周期あたり浮動小数約 60 回）。
- プロセス雑音の調整値は `q_td=3e-3, q_bias=3e-3, q_th=1e-3`。
  **±20〜30% のモデル誤差があっても角度推定誤差 0.23°**（`src/tune_kf.py` でスイープ済み。感度は非常に鈍い＝現地で悩む必要がない）。

### 副産物が強い

`τ̂_d` は**そのまま「坂の勾配計」**になる（`α̂ = asin(−τ̂_d /(m g r))`）。
傾斜センサを積まずに、坂・シーソー・段差の検出ができる。ゾーン判定や減速判断にも使える。

## 3. 制御則

### 位置保持（ゾーンA：直立15秒）
`u = −K_pos·[φ, θ, φ̇, θ̇]`（LQR）。ここで φ を効かせるので、その場から動かない。
HPF 構成だと 15 秒で **31 cm** 流れるが、KF 構成では **0.6 cm**。

### 走行（ゾーンB〜E）
速度追従の **LQI**：`z = [θ, φ̇, θ̇, ∫(φ̇ − φ̇_ref)]`、`u = u_eq − K·z`。
位置 φ は制御しない（コースを進むので戻す必要がない）。

### 外乱前置補償（坂対策の本体）
τ̂_d が分かっているので、その坂での**平衡点を直接作れる**：

```
u_eq  = −τ̂_d                      （坂を保持するのに必要なトルク）
θ_eq  = k_ff · u_eq / (m_b g l)    （坂では「坂の分だけ前傾」が正解）
```

`u = u_eq − K·(z − z_ref)` とすると、坂に入った瞬間に姿勢目標が切り替わる。積分器が効いてくるのを待たない。

> ### ⚠ ここに罠がある（実験で踏んだ）
> `k_ff = 1.0` にすると **入力ゲイン誤差（Kt・ギヤ効率の同定誤差）に対して正帰還ループが立つ**。
> ```
> ∂u/∂τ̂_d = −1 + K_θ/(m_b g l) ≈ +6.4
> ループゲイン ≈ 6.4 × (入力ゲイン誤差)   →  誤差 16% 超で発振
> ```
> 実際 Kt を −21% ずらした機体で、平地なのに θ_eq が 8° に張り付いて電流飽和 → 走行不能になった。
> 対策：**k_ff = 0.6**、**θ_eq を ±6°で飽和**（坂20°相当。物理的にあり得ない値を出させない）、
> **τ̂_d を 0.2 s で低域通過**。これで Kt が ±25% ずれても完走する（検証済み）。
> **そして何より、実験2（下記）で Kg を 10% 精度で同定しておくこと。**

### 制御配分（S字で転ばないため）
左右モータの電流上限は各々 ±2 A。`|τ_L| , |τ_R| ≤ τ_max ⇔ |S| + |D| ≤ 2τ_max`
（S=合計トルク=倒立、D=差トルク=旋回）。**倒立を先に確保して、余った分だけ旋回に配る。**
これをやらないと S字で旋回指令が電流を食い潰して倒立側が飽和する。

### 参照ガバナ＋転倒復帰
- 電流飽和が続く / 姿勢が崩れたときだけ目標速度を落とす（**坂そのものでは減速しない**。坂は前置補償で吸収するので減速不要）。
- `|θ − θ_eq| > 22°` で全力で足を出す復帰モード。

### パス追従
エンコーダのデッドレコニングで自己位置 (x, y, ψ) を持ち、
中心線のウェイポイント列に **Stanley 法**（`ψ_ref = ψ_path − atan(k·e_lat /(v+0.15))`）で追従。
ウェイポイント表 `firmware/pace.h` は `src/gen_pace.py` がコース定義から自動生成する。
**当日は練習走行でコースを実測して数値を直し、再生成するだけ。**

## 5. これ以上やるなら（費用対効果は落ちる）

- **MPC**：LPC1343（FPUなし・RAM 8KB）でオンライン QP は現実的でない。やるなら explicit MPC か、
  1ステップ先の飽和だけ見る簡易版。今の「LQI＋ガバナ＋配分」で実質同じ効果が取れているので優先度は低い。
- **ゲインスケジューリング**：τ̂_d で K を切り替える。坂での応答をさらに詰めたいときの手。
- **摩擦補償**：ギヤのクーロン摩擦を `tanh` で前置補償（`sim.run(..., fric_ff=1.0)` で試せる）。
  低速域の粘りが改善するが、チャタリングに注意。
- **シーソー専用ロジック**：τ̂_d の符号反転を検出したら一瞬だけ速度指令を 0 にして重心を送る、など。
  シミュレータに `E_seesaw` シナリオがあるので試せる。
