## 2. ビュートバランサー2（VS 製）のハード事実

| 項目 | 値 | 出典 |
|---|---|---|
| CPU | ARM Cortex-M3 **LPC1343**（72MHz, FPUなし, RAM 8KB, Flash 32KB） | 製品仕様 |
| 寸法 / 重量 | 177(H)×90(W)×42(D) mm / **約150 g** | 製品仕様 |
| **重心位置** | 車軸から **Y = 74.5 mm** | 取説 11.4 寸法図 |
| タイヤ | **φ42 mm**（半径 21 mm）ラバー | 取説 11.2 |
| 減速比 | **21 : 1** | 取説 11.2 |
| モータ | FA-130-2270 ×2 | 製品仕様 |
| **ジャイロ** | 村田 **ENC-03RC/D**、±300 deg/s、**分解能 1.2025 deg/s**、取得周期 **2 ms** | 取説 11.1 |
| **加速度センサ** | **無い** ← 最重要 | 製品仕様（センサはジャイロ×1 + エンコーダ×2 のみ） |
| エンコーダ | 4逓倍、速度分解能 0.01247 rad/s、最大 100 kpps | 取説 11.2 |
| **モータ入力** | **電流指令（mA）**。1 kHz の PI 電流制御が内蔵、分解能 1.61133 mA | 取説 11.3 |
| 制御周期 | `MAIN_CYCLE = 500 Hz`（電流 1000 Hz、VS-C3 等 100 Hz） | Balancer2.h |
| 電源 | 単3 ×2（3V 系） | 製品仕様 |

**ここが効く 2 点**

1. **入力が「電圧」ではなく「電流」**＝実質トルク指令。モータの電気系をモデルから消せるので、
   モデルベース制御（LQR/カルマン）の精度が出しやすい。教科書どおりの式がそのまま使える。
2. **加速度センサが無い**＝「重力方向」を直接測る手段がない。
   純正はジャイロ積分に HPF を掛けてドリフトを捨てているが、HPF は**定常的な傾きを必ず 0 に引き戻す**。
   坂・シーソーでは角度を原理的に誤る。ここが本コンテストの最大の技術的ボトルネックであり、勝ち筋。

## 3. 純正ファームウェアの中身（GitHub: vstoneofficial/Balancer2）

公式サンプル `Balancer2_firm_Simple/src/control.c` の倒立制御はこれだけ：

```c
out  = GAIN_BODY  * (GAIN_BODY_ANGLE*BODY_ANGLE + GAIN_BODY_ANGULAR_SPD*BODY_ANGULAR_SPD);
out += GAIN_WHEEL * (GAIN_WHEEL_ANGLE*wheel_angle + GAIN_WHEEL_ANGULAR_SPD*wheel_spd);
out ±= GAIN_WHEEL_CORRELATION * (左右差の角度・角速度);
T_CURRENT_L = (short)out;   // mA
```

既定ゲイン：`BODY_ANGLE=-36400, BODY_ANGULAR_SPD=-5460, WHEEL_ANGLE=1320, WHEEL_ANGULAR_SPD=396`

- **これは PID ではなく、既に 4 状態フィードバック（手調整された LQR）**。
  だから「PID を頑張る」は的外れで、**同じ土俵（状態FB）で殴っても大差はつかない**。
  差がつくのは **推定（角度・外乱）** と **サーボ構造（目標速度への追従）** の方。
- 角度 `BODY_ANGLE` はライブラリが HPF 付きジャイロ積分で作っている（係数 `GAIN_GYRO_HPF_COF=0.9995`）。
  500 Hz なので時定数は約 2 秒。**2 秒以上続く傾きは推定から消える。**
- **公式サンプルに単位のバグがある**（要現地確認）:
  ```c
  wheel_L_angular_spd = WHEEL_ANGULAR_SPD_L - (T_SPD_L / MAIN_CYCLE);   // ← /MAIN_CYCLE は不要
  ```
  `T_SPD` は rad/s なので、角速度の偏差から引くときに 500 で割ってはいけない（角度側の
  `Tspd_i += T_SPD/MAIN_CYCLE` は正しい）。このままだと目標速度を与えても速度項が 1/500 しか効かず、
  位置項だけで引っぱることになる。**直すだけで速度追従が良くなる。**
- VS-C3 操縦時の最大速度は `9.42 rad/s` = **0.20 m/s**。純正の想定速度はこの程度。

## 4. 使えるインフラ（これは素直に使う）

- `CycleProc()` が 500 Hz の同期をとってくれる。`getSW()`、`setLED()`、`Wait()`。
- `calibrarion()`（公式サンプル）でジャイロ静止オフセットを平均化。
- **ログ機能**：500 Hz で memmap の任意アドレスを内蔵 Flash に記録し、PC ツール（バランサー2プログラマ）で回収できる。
  `USER_ARIA1〜8`（double×8）は自由に書けるので、**推定値をここに出しておけば実機で推定器の検証ができる**。
  → これがあるので「現地で推定器が効いているか」を目で確かめられる。必ず使う。
