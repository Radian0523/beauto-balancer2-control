### A-2. 理論の最低限（各30分で足りる）

1. **状態空間表現と LQR**：`u = -Kx`。重みは Bryson の規則（`Q_ii = 1/x_max²`）で決める。
   「ゲインを回す」のではなく「許容する振れ幅を決める」。これだけで手調整から解放される。
2. **カルマンフィルタ**：予測（モデル）＋更新（観測）。定常ゲインを事前計算すれば実装は行列積だけ。
3. **可観測性**：なぜ加速度センサ無しで絶対角が出せるのか（＝車輪の動きが角度の情報を持っている）。

## B. Day 1：符号 → 同定 → 直立

### B-1. 最初の 30 分：符号 3 点セット（ここを飛ばすと一日溶ける）

`firmware/main_bb2.c` の `SIGN_GYRO / SIGN_WHEEL / SIGN_CUR` を実機に合わせる。

| 確認 | やり方 | 期待 |
|---|---|---|
| ジャイロの向き | 機体を**前に**傾け、`BODY_ANGULAR_SPD` の符号を見る | 正 → `SIGN_GYRO=+1` |
| 車輪の向き | `T_CURRENT_L/R` に +300 を書く | 前進 → `SIGN_CUR=+1` |
| エンコーダが本体基準か | 車輪を手で押さえて**本体だけ**傾ける | `WHEEL_ANGLE` が動けば相対（＝KF の仮定どおり） |

3 つ目が「動かない（絶対角）」だった場合は、KF の観測行列 `C` の 1 行目を `[1,0,0,0,0,0]` に変える
（`src/design.py` の `design_kf` 内、1行だけ）。

### B-2. 同定（15分）：`docs` より先にこれをやる

| 実験 | 手順 | 得られるもの |
|---|---|---|
| **1. 振り子落とし** | 電流制御OFF、1〜2°傾けて手を離し、ジャイロを 500Hz ログ（0.3秒でよい） | 不安定極 λ → `J_b` |
| **2. 車輪空転** | 本体を手で固定、タイヤを浮かせて 500 mA ステップ、車輪角速度をログ | 立上り勾配 → `Kg2/Jw_eq`、定常速度 → `Ke·n` |
| **3. 定常電流** | 実験2 を 200/500/1000 mA で繰り返す | 粘性・クーロン摩擦 |

同定したら `src/params.py` を書き換えて:

> **必ず見ること**：公称パラメータだと、設計ゲインは純正既定値より **4 倍ほど柔らかい**
> （θ ゲイン: 16,000 mA/rad vs 純正 36,400 mA/rad）。
> どちらが正しいかは実機の `Kg`（＝実験2）次第。**ここが合っていないと外乱前置補償が発振する**（`docs/02` の罠）。
> 同定が終わるまでは `BB2_K_FF = 0.3` くらいに落としておく。

### B-3. 直立させる順番（一気に全部入れない）

1. `BB2_USE_GOV=0, BB2_K_FF=0` でまず **HOLD モードだけ**。その場で立てば推定と LQR は生きている。
2. `USER_ARIA1〜8` をバランサー2プログラマでグラフ表示。
   **本体を手でゆっくり 10° 傾けて放したとき、`th_hat` が 10° を指して戻ってくるか**を目で確認。
   ここで純正 HPF との違いが一目で分かる（HPF は 2 秒で 0 に戻ってしまう）。
3. `BB2_K_FF` を 0.3 → 0.6 に上げ、**本を1冊敷いた坂**に乗せて `taud_hat` が出るか確認。
4. 走行モード（速度 0.2 m/s）→ 0.35 m/s。

## C. Day 2：コースを測る → ペースノート → 速度を上げる

1. **コースを実測**（これが一番効く）：各ゾーンの長さ、坂の角度（スマホの傾斜計でよい）、
   S字の振れ幅と走路の幅、シーソーの支点位置。
2. `src/mission.py` の寸法を実測値に置換 → `python3 src/gen_pace.py` → `run_c_check.py` で通るか確認 → 焼く。
3. 速度を 0.05 m/s ずつ上げ、**シミュレータで先に**限界を見てから実機で試す。
   スコアは「①どこまで ②時間」なので、**完走の確実性が先、速度は後**。
   シミュレーション上は 0.9 m/s でも通るが、実機はタイヤのスリップ・段差の衝撃・バックラッシュがあるので
   **0.4〜0.5 m/s を狙い、余力があれば上げる**のが現実的。
4. 毎回ログを取る。転倒したら `th_hat` と `taud_hat` を見れば「推定が壊れた」のか
   「トルクが足りない」のか「飽和した」のかが切り分けられる。

- **電池は本番直前に新品**。`V_bat` が下がると `Kg` が実質下がり、同定した値からずれる。

## E. 現場で詰まったときの切り分け表

| 症状 | 見るところ | 対処 |
|---|---|---|
| 立つがじわじわ流れる | `th_hat` の定常値、`bias_hat` | キャリブレーションやり直し。KF なら本来ほぼ出ない |
| 立つが小刻みに振動 | 電流の飽和率、`K_VEL[0]` | `u_max` を上げる（＝ゲインを下げる）／ `rho` を上げて再設計 |
| 坂で加速して吹っ飛ぶ | `taud_hat`, `th_eq` | `BB2_K_FF` を下げる。`θ_eq` が 6° に張り付いていたら同定がずれている |
| 平地なのに `th_eq` が張り付く | 入力ゲイン誤差による正帰還（`docs/02` の罠） | `K_FF` を 0.3 に、実験2 をやり直す |
| S字で転ぶ | 左右電流が同時に ±2A に張り付いていないか | 制御配分が効いているか確認（倒立優先） |
| シーソーで倒れる | `taud_hat` の反転タイミング | シーソー区間の目標速度を下げる（`gen_pace.py`） |
| 走行距離がずれる | デッドレコニング vs 実測 | タイヤ半径 `WHEEL_R` を実測値に（空転すると必ずずれる） |
